# TASK locations-2026-09 — точки внутри организации (spec, заморожено 2026-09-05)

Дизайн: `docs/superpowers/specs/2026-09-05-locations-design.md`.

## Цель

Организация с `perLocationJournals = true` и ≥ 2 зданиями (`Building`)
ведёт документы журналов отдельно по каждой точке; сотрудники общие; в
шапке сайта и в Mini App — переключатель точки; анкета после регистрации
создаёт точки по числу «Точек».

## Acceptance criteria

- **AC1. Схема.** `Organization.perLocationJournals`, `JournalDocument.buildingId`
  (+relation SetNull, index), `JournalObligation.buildingId` (+relation),
  `User.buildingIds String[]`. `npx prisma db push` на локальной БД
  проходит без предупреждений о потере данных; `prisma validate` зелёный.
- **AC2. Активная точка.** `POST /api/me/active-building` ставит cookie
  `wesetup.building=<orgId>:<buildingId>`; чужая точка → 403;
  выключенный флаг или < 2 точек → `activeBuildingId = null`; пользователь
  с `buildingIds=[B]` не может выбрать A (403) и по умолчанию находится в B.
- **AC3. Шапка.** При `canSwitch` рядом с названием организации пилюля с
  названием точки и выпадающим списком; при одной точке или выключенном
  флаге пилюли нет. Переключение обновляет страницу и список документов.
- **AC4. Документы.** В `/journals/<code>` и `GET /api/journal-documents`
  видны документы активной точки и документы без точки; документ другой
  точки не виден. Созданный через диалог документ получает `buildingId`
  активной точки. В шапке документа и в PDF под названием организации —
  строка точки с адресом.
- **AC5. Автосоздание.** `ensureActiveDocument` с `buildingId` создаёт по
  документу на каждую точку и не дублирует, пока жив общий (null) документ
  того же периода; `closeExpiredDocuments` закрывает документ только при
  преемнике той же точки/общем; broken-chains восстанавливает по точкам
  (юнит-тесты).
- **AC6. Анкета.** «Точек» = N ≥ 2 → создаются здания «Точка 1…N» (первое
  с адресом организации), `perLocationJournals = true`; N = 1 → ничего не
  создаётся, флаг не трогается. Повторное сохранение не создаёт дублей.
- **AC7. Настройки.** `/settings/buildings` называется «Точки и помещения»,
  при ≥ 2 зданиях виден тумблер «Вести журналы отдельно по точкам»
  (PATCH), хаб настроек и хлебные крошки обновлены.
- **AC8. Сотрудники.** Диалоги добавления/редактирования сотрудника при
  включённом флаге показывают чипы «Точки»; `POST /api/staff` и
  `PATCH /api/staff/[id]` принимают `buildingIds` (только точки организации);
  карточка сотрудника показывает точки.
- **AC9. Обязательства.** `dedupeKey` без точки не меняется
  (`daily:<date>:<code>`), с точкой — `daily:<date>:<code>:<buildingId>`;
  сотрудник на двух точках получает два обязательства по журналу;
  сотрудник с `buildingIds=[B]` не получает обязательство по точке A;
  `OpenJournalObligation.buildingName` заполняется (юнит-тесты).
- **AC10. Mini App.** `/api/mini/home` отдаёт `location`; на `/mini/me`
  блок переключения точки; обязательства показывают точку; переход из
  обязательства другой точки переключает cookie через
  `/api/me/active-building/go` и открывает нужный путь.
- **AC11. Пул задач и TasksFlow.** `activeDocFor` учитывает точку;
  org-scoped `scopeKey` содержат сегмент точки при активной точке;
  рассылка задач идёт по каждому документу дня; заголовок/описание задачи
  и сводка проверяющему содержат название точки (юнит-тест на хелпер
  подписи).
- **AC12. Партнёры/ROOT.** Партнёр уровня «просмотр» в кабинете клиента
  может переключать точки (`/api/me` в allowlist) и не может создавать
  (`POST /api/settings/buildings` → 403 по guard'у записи); cookie с чужим
  `orgId` игнорируется.
- **AC13. Качество.** `npm run typecheck`, `npm run lint`, `npm test`
  зелёные; e2e-скрипт на dev (Playwright, Chrome) с организацией из двух
  точек подтверждает AC3, AC4, AC10 скриншотами.
- **AC14. «Что нового».** Категория про точки добавлена,
  `LATEST_NOTES_BUILD_SHA` указывает на коммит с фичей.
