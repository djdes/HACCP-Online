# cold-readings-2026-09 — холодильное оборудование: несколько замеров в день, минус с телефона

Источник: обращение заказчика 2026-09-18. Заморожено 2026-09-18.

## Проблема
1. По QR с телефона нельзя ввести отрицательную температуру морозилки: цифровая клавиатура (`inputMode="decimal"`)
   не содержит минуса.
2. «Нет возможности сделать периодичность контроля — 2 раза в смену»: режим оборудования «2/3 раза в день» в окне
   оборудования есть, но ни на что не влияет — сетка хранит одно значение в день.

## Acceptance criteria
- **AC1** Формы `/equipment-fill` и `/room-fill`: кнопка «−» рядом с полем температуры переключает знак; у объекта с
  нормой ниже нуля минус стоит сразу (и после «ещё замер»); отрицательное значение сохраняется (e2e).
- **AC2** Модель совместима: первый замер — `temperatures[id]`, второй и третий — `temperatures["id#2"|"id#3"]`.
  `expandColdEquipmentReadingSlots`, `pickColdReadingSlotForWrite`; пустая строка, синхронизация с конфигом,
  автозаполнение и отклонения работают по слотам (юнит-тесты).
- **AC3** Журнал: у оборудования с режимом «2/3 раза в день» строки «1-й замер», «2-й замер» в таблице, карточках
  «сегодня», списке по оборудованию и мастере заполнения; прогресс дня считает слоты; значения разных сотрудников за
  одну дату сливаются в одну строку сетки (e2e).
- **AC4** QR: скан пишет в первый пустой замер дня (с учётом записей всех сотрудников), при заполненных — в последний;
  утренний замер не затирается (e2e).
- **AC5** PDF печатает строки по замерам и сливает записи сотрудников за дату (e2e).
- **AC6** «Что нового»: категория «Температура холодильников». typecheck, lint, юнит, e2e, регрессия
  `qr-a4-temperature-2026-09/e2e/poster-scan.ts`; прод-смоук после деплоя.

## Ограничения
- Старые документы и TasksFlow пишут только первый замер — поведение не меняется.
- e2e только на `wesetup_e2e` (localhost:5432).
