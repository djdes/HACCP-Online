# qr-a4-temperature-2026-09 — A4-плакаты с QR и ввод температуры без входа

Источник: план `cached-nibbling-magpie.md`, Задача 3 (ТЗ п.2). Заморожено 2026-09-15.

## Проблема
Заказчик хочет повесить на склад и холодильник лист A4 с QR-кодом: сотрудник сканирует телефоном,
вводит температуру (и влажность для склада) — запись попадает в журнал за сегодня, без входа в кабинет.
Сейчас есть только мелкие наклейки для холодильников; у помещений QR нет вовсе, а QR холодильника
пишет влажность под несуществующий ключ и молча отвечает «ok», когда писать некуда.

## Acceptance criteria
- **AC1** `/settings/qr-posters?kind=rooms|equipment[&ids=…][&doc=<id>][&origin=]` (management): на каждой A4-странице
  один объект — крупно название (+ точка/цех и норма мелко), QR ≈110 мм по центру, снизу три строки «1. Наведите камеру
  телефона на код. 2. Выберите своё имя и введите показания. 3. Нажмите «Сохранить» — запись попадёт в журнал за сегодня»;
  `@page { size: A4 portrait; margin: 14mm }`, `break-after: page`, `break-inside: avoid`; кнопка «Распечатать»; у каждого QR
  `data-qr-url`/`data-qr-kind`/`data-qr-id`; `?doc=` ограничивает список строками документа.
- **AC2** Кнопки-входы: `DocumentActionsBar.menuItems` «QR-плакаты» в документах климата и холодильников (сайт и Mini App),
  `/settings/equipment` рядом с «QR-наклейки» («Плакаты A4»), `/settings/buildings` («QR-плакаты помещений»).
- **AC3** `/room-fill/[roomId]?token=…` без входа: проверка токена (истёк/повреждён → карточка ошибки), название склада,
  нормы, поля «Температура»/«Влажность» по `enabled`, выбор сотрудника из ростера (localStorage
  `wesetup.room-fill.employeeId`), ближайший срок контроля, предупреждение вне нормы, «Сохранить» → «Записано в бланк за
  сегодня, 10:00».
- **AC4** `POST /api/room-fill/[roomId]`: токен → помещение → организация → активный `climate_control` на сегодня с учётом
  точки → строка помещения (нет — добавить из справочника) → merge в `measurements[row.id][slot]` (соседние склады и сроки
  сохраняются), upsert `(documentId, employeeId, date)`; сотрудник ∈ ростер (404); нет активного документа → 409
  `no-active-document`; отклонение t° → `processTemperatureReading` (`source: "<имя> (QR)"`), влажность вне нормы — флаг.
- **AC5** Лимит `qrFillRateLimiter` (30/мин, ключ `ip:объект`) → 429 с русским текстом; `recordAuditLog` `journal.qr_fill` на
  каждую успешную запись — в обоих маршрутах; `equipment-fill` вместо `{ ok, touched: 0 }` → 409.
- **AC6** Токен другой организации/испорченный/просроченный → 401; токен помещения не принимается маршрутом оборудования.
- **AC7** Влажность с QR холодильника попадает в строку климата цеха (`room-area-<areaId>` / имя цеха), не под id оборудования.
- **AC8** `robots.ts`, `cookie-consent.tsx`, `route-titles.ts` учитывают `/room-fill` и `/settings/qr-posters`; сканер Mini App
  открывает ссылки `/room-fill` и `/equipment-fill`.
- **AC9** Самопроверка «сканированием»: скрипт открывает плакаты, берёт `data-qr-url`, открывает в новом cookie-less контексте —
  форма без редиректа на `/login`; норма и отклонение → записи в `JournalDocumentEntry`, `AuditLog`, инцидент отклонения;
  скриншоты плаката (`page.pdf` A4) и формы. Прод: только чтение.

## Ограничения
- Формат токена оборудования не меняется (расклеенные наклейки работают).
- e2e только на `wesetup_e2e` (localhost:5432).
