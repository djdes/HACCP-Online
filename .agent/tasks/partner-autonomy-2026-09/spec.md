# Панель платформы, карточка партнёра и самостоятельность партнёра

Задача владельца от 2026-09-11, три пункта.

## Что просили

1. В панели платформы список разделов не помещается на страницу.
2. В партнёрах нужна возможность редактировать название и всё, что можно.
3. Партнёр в своём кабинете должен уметь редактировать организации клиентов
   и создавать организации сам.

## Решения владельца (AskUserQuestion, зафиксированы до реализации)

| Вопрос | Решение |
|---|---|
| Меню платформы | Группы в выпадашках |
| Чья организация, созданная партнёром | Клиента: свой Account, своя подписка |
| Уровень доступа | Партнёр переключает сам |
| Где партнёр правит данные организации | Inline на карточке клиента |
| Объём правки в ROOT | Всё, включая реквизиты для выплат |

## Критерии приёмки

- **AC1.** На `/root` при 1920, 1280 и 360 px ни один пункт меню не выходит за
  край, горизонтальной прокрутки страницы нет.
- **AC2.** Активный раздел и его группа подсвечены; `aria-current="page"` стоит.
- **AC3.** В меню есть `/root/audit`, `/root/audit-impersonations`, `/root/timings`
  — раньше страницы существовали без ссылок.
- **AC4.** `PATCH /api/root/partners/[id]` меняет только присланные поля; пустое
  тело — 400; каждая правка в аудите с before/after, счёт маскирован.
- **AC5.** Смена slug на занятый — 409; на свободный — работает и требует
  подтверждения (старая ссылка ломается).
- **AC6.** Правка реквизитов требует ввода слова и шлёт партнёру письмо + Telegram.
- **AC7.** `PATCH /api/root/partners/[id]/clients/[orgId]` меняет уровень доступа.
- **AC8.** `POST /api/partner/clients` создаёт организацию с `source: "manual"`,
  `accountId = null` без владельца и с собственным Account при указанном владельце.
- **AC9.** Отказы: свой ИНН — 409 `own_organization`; почта сотрудника партнёра —
  409 `partner_team_email`; занятая почта — 409 `email_taken`; 10 непереданных —
  409 `too_many_pending`; 6 создание за час — 429.
- **AC10.** `POST /api/partner/clients/[orgId]/owner` назначает владельца,
  переотправляет приглашение (не чаще раза в сутки на тот же адрес) и меняет
  адрес до принятия; после принятия — 409 `already_owned`.
- **AC11.** `PATCH /api/partner/clients/[orgId]` правит реквизиты организации
  только своего клиента (чужой — 404), отвергает свой ИНН, пишет аудит
  `partner.org_updated`.
- **AC12.** `PATCH /api/partner/clients/[orgId]/access-level` меняет уровень и
  шлёт клиенту три уведомления; чужой клиент — 404.
- **AC13.** Партнёр в кабинете клиента не видит анкету «Завершите регистрацию»,
  `POST /api/profile/complete` из партнёрской сессии — 403.
- **AC14.** Анкета, если показана, стартует от известных данных организации.
- **AC15.** `npx tsc --noEmit`, `npm run lint` по затронутым каталогам,
  `npm run test:gate` и парити-сборка webpack — зелёные.

## Ограничения

- Схема Prisma не меняется: признак «завёл партнёр» — существующее значение
  `PartnerClient.source = "manual"`.
- Никаких правок `PARTNER_DENYLIST` ради новых роутов: `/api/partner/**` уже в
  allowlist.
- `PATCH /api/settings/organization` не переиспользуется: он берёт цель из
  `getActiveOrgId(session)`.
