## Original task statement
В карточке помещения (/settings/buildings, при добавлении и редактировании) добавить «кто убирает» (мультивыбор) и необязательного «кто проверяет» (мультивыбор). Назначения применяются в журнале уборки: показываются под названием помещения и в настройках; нижние строки журнала переименовать в «Старший по уборке» / «Контролёр». Несколько проверяющих: первый — проверяющий задачи в TasksFlow, все — вечерняя сводка по своим помещениям. Единственное место закрепления — карточка помещения.

## Решения владельца (2026-09-04)
1. Нижние строки → «Старший по уборке» / «Контролёр».
2. Только карточка помещения закрепляет уборщиков/проверяющих; сетка «Закрепить зоны» в документе убирается, старые закрепления переносятся скриптом.
3. Первый проверяющий — verifier задачи в TF; сводка — каждому проверяющему по его помещениям.
4. Все журналы с помещениями — общий справочник Room (фаза 2, отдельные task-id).

## Acceptance criteria
- AC1: `applyRoomResponsiblesToConfig` — DB-уборщики комнаты заменяют закрепление; комнаты без DB-уборщиков сохраняют legacy-закрепление/пул; пул = raw + новые в порядке selectedRoomIds; неизвестные id отброшены; комнаты вне selectedRoomIds игнорируются; вход не мутируется. Тесты.
- AC2: `verifierByRoomId: Record<string, string[]>`; legacy string коэрцится; `resolveRoomControllers` цепочка комната → controlUserId → controlResponsibles[0]; `resolveRoomController` = первый. Тесты.
- AC3: Карточка помещения: «Кто убирает» / «Кто проверяет (необязательно)» мультивыбор (группы Рекомендуем/Можно/Не рекомендуем, поиск, подсказка нагрузки); PATCH /api/settings/rooms/[id] принимает массивы, проверяет принадлежность организации и активность, дедуп, max 30.
- AC4: Журнал уборки (десктоп и мобильные карточки = Mini App): под помещением «Уборка: …» и «Проверяет: …» (последнее — только при своих проверяющих); клик открывает карточку помещения.
- AC5: TF-адаптер, cell-override-sync, PDF и валидация PATCH документа читают эффективный конфиг; пустой пул + DB-уборщики → документ сохраняется.
- AC6: После «Добавить помещение» открывается карточка нового помещения.
- AC7: Строка помещения в /settings/buildings показывает «Убирает: …» / «Проверяет: …» или «Уборщики не назначены».
- AC8: Подписи нижних строк из `CLEANING_ROW_LABELS` (экран, карточки списка, PDF); хранимые `title` не меняются.
- AC9: Вечерняя сводка (cron cleaning-control-digest) уходит каждому проверяющему только по его помещениям; контролёр документа — по остальным; rowKey `control::{doc}::{date}` (документ) / `control::{doc}::{date}::{verifier}`; webhook штампует controllerCompletedAt только по помещениям этого проверяющего; повторный запуск — no-op. Тесты парсера/scope.
- AC10: `npm test`, `npm run typecheck`, `npm run lint` зелёные (lint — только унаследованные warnings); `whats-new-notes.ts` обновлён.

## Constraints
- Эффективный конфиг никогда не сохраняется в документ (клиент шлёт raw).
- Никаких прямых записей в TF БД; создание задач — как раньше (TF API + TasksFlowTaskLink).
- Смена уборщиков помещения не перераздаёт уже созданные сегодня TF-задачи (документировано в подсказке карточки).
