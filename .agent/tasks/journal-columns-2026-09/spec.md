# journal-columns-2026-09 — колонки таблиц журналов: скрыть, показать, переименовать

Источник: план `cached-nibbling-magpie.md`, Задача 4 (ТЗ п.6 — колонки). Заморожено 2026-09-15.

## Проблема
Заказчик хочет включать и выключать колонки таблиц журналов и переименовывать их, для одного документа
или сразу для всех документов журнала. Начать с бракеража готовой продукции (`finished_product`) и
бракеража скоропортящейся продукции (`perishable_rejection`). Сейчас у готовой продукции есть только
четыре флага `showX` в настройках, у скоропорта — один `showNote`; переименовать колонку нельзя.

## Acceptance criteria
- **AC1** `src/lib/journal-columns.ts`: реестр колонок `finished_product` (11) и `perishable_rejection` (11,
  включая `note`); старые флаги (`showProductTemp`, `showCorrectiveAction`, `showOxygenLevel`, `showCourierTime`,
  `showNote`) привязаны к своим колонкам; `config.columns = { hidden: string[]; labels: Record<string,string> }`;
  `resolveColumns(code, config, orgDefaults?)` с приоритетом `config.columns` → общий вариант организации →
  старые флаги → реестр; обязательную колонку скрыть нельзя, неизвестные ключи отбрасываются, подпись ≤ 60
  символов, пустая или стандартная подпись не хранится (юнит-тесты).
- **AC2** Документы без `columns` выглядят как раньше. Нормализаторы обоих журналов сохраняют `columns` и при
  его наличии синхронизируют старые флаги (`legacyFlagsFromColumns`), поэтому PDF и адаптеры TasksFlow,
  читающие флаги, не расходятся с таблицей; PDF берёт подписи и видимость из `resolveColumns`.
- **AC3** «Настройки журнала» обоих журналов — раздел «Колонки таблицы»: переключатель видимости и
  переименование; обязательные колонки — неактивный переключатель с подсказкой «Обязательная колонка бланка»;
  правый клик / долгое нажатие по заголовку колонки — меню «Переименовать», «Скрыть колонку», «Применить ко всем
  документам»; сохранение для документа — существующий PATCH `config`; данные скрытой колонки не удаляются.
- **AC4** «Применить ко всем документам журнала» → `ConfirmDialog` (последствия списком, выбор объёма: новые и
  активные / все / только новые) → `PUT /api/settings/journal-columns/[code] { columns, applyTo }` (права
  управления журналами): набор сохраняется в `Organization.journalColumnsJson[code]` и **записывается** в
  `config.columns` (+ старые флаги) документов выбранного объёма, заменяя их личные настройки; toast «Обновлено:
  N документов»; новый документ журнала получает общий набор при создании.
- **AC5** Таблица, карточный вид (телефон и Mini App), диалог строки и PDF показывают одинаковый набор и подписи.
- **AC6** typecheck, lint, test:gate чистые; e2e локально на обоих журналах; прод — только чтение.

## Ограничения
- Схема: только `Organization.journalColumnsJson Json @default("{}")`.
- Модель «копия», а не «наследование»: общий набор копируется в документы, чтобы печать и TasksFlow, читающие
  флаги из конфига документа, не требовали правок.
- Правка в двух клиентах (`finished-product-document-client.tsx`, `perishable-rejection-document-client.tsx`) и
  печати этих журналов; остальные журналы не трогаем.
- e2e только на `wesetup_e2e` (localhost:5432), никогда на `.env` (5433 = прод).
