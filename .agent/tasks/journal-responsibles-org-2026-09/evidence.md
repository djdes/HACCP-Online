## Исправления после раунда 1

- **AC8.** Общий адаптер (`med_books`, `fryer_oil`, `sanitary_day_control` и другие журналы без своего адаптера),
  журнал жалоб и уборка (уборщик и проверяющий из rowKey) теперь сверяют сотрудника с организацией документа
  через `findTaskEmployee`. Смоук-гвард разбирает каждый адаптер деревом TypeScript: если `applyRemoteCompletion`
  разбирает rowKey на сотрудника, в нём обязан быть `findTaskEmployee`/`findOrgUser`. Гвард проверен на
  версиях из `HEAD`: срабатывает на `generic.ts`, `complaint-register.ts`, `cleaning.ts`, молчит на `hygiene.ts`.
  e2e: `med_books`, `fryer_oil`, `complaint_register` с сотрудником B → `false`, ни записи, ни строки.
- **AC3.** Ветка «у документа нет ответственного — взять из конфига» удалена. Ответственный меняется только явным
  выбором: полем `responsibleUserId` или изменённым выбором внутри `config` (`pickChangedConfigResponsible`).
  Формулировка AC3 уточнена в `spec.md` (раздел «Уточнения»): буквальное прочтение сломало бы ~13 диалогов
  настроек, которые выбирают ответственного внутри `config`. e2e: «PATCH прежнего конфига документа без
  ответственного → ответственного нет» и «выбор ответственного в настройках реестра → ответственный документа».
- **Сверх вердикта** (замечание верификатора): `prisma/seed-admin.ts` больше не меняет пароль и роль аккаунта
  `admin@haccp.local`, если он живёт в реальной организации, — скрипт ничего не трогает и просит `ADMIN_EMAIL`.

## Доп. коммит после вердикта (замечания верификатора, раунд 2)

- **Сохранение с прежним ответственным.** PATCH считает выбором только ДРУГОГО человека: клиенты уборки и
  контроля стекла шлют текущего ответственного при каждом сохранении, и уволенный ответственный больше не
  даёт 400 на сохранение ячеек. Новый ответственный получает в шапку должность из карточки сотрудника.
- **Входной контроль.** Диалог создания не предвыбирает первого сотрудника и «Управляющего», создаёт документ
  без строк-образцов (раньше в каждый новый документ попадали поставки «ООО Метро», «Агро-Юг»). Ответственный
  по умолчанию — по правилам ростера, не аккаунт «имя = почта».
- **Формы строк без «первого в списке»:** универсальные журналы учёта `tracked-document` (настройки и новая строка), чек-лист
  вентиляции, контроль стекла, мойка оборудования (контроль — руководство по правилам ростера), инструктажи,
  интенсивное охлаждение, фритюр. Автор строки — вошедший сотрудник или явный выбор; некому — подсказка.
- **Дезинсекция.** Удалён клиентский сеятель, который в любой организации создавал документы с записями 2025 года
  («ИП Хижняк», «пропан»). Образцы сеет только сервер и только в демо-организации.
- **Гварды:** смоук-тест запрещает `users[0]`/`employees[0]` в клиентах журналов и `ensureSample*(` в клиентских
  компонентах; оба срабатывают на версиях из `HEAD`.
- **Проверки:** typecheck чисто; юнит 111/111 и 5/5 (`acceptance-document.test.ts`); e2e `create-docs` 73/73
  (новые: смена ответственного → должность из карточки, прежний уволенный ответственный → 200, документ из
  диалога входного контроля без строк-образцов, открытие дезинсекции не создаёт документов), `verify-docs` 28/28.
