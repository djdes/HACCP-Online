# Journal `finished_product` — Журнал бракеража готовой пищевой продукции

**Tier:** B (обязательный для соц.учр.: школы, сады, больницы, санатории), C-recommended для коммерческого общепита
**СанПиН:** Прил. № 4 к СанПиН 2.3/2.4.3590-20
**Status:** draft

## Назначение

Бракеражная комиссия (1-3 человека, утверждена приказом) перед каждой
раздачей готового блюда — органолептика и решение о допуске к подаче.
Это «последний рубеж» перед потребителем.

## Колонки таблицы (точная норма)

| # | Колонка | Тип | Обяз. | Нормативный пин |
|---|---------|-----|-------|-----------------|
| 1 | Дата и час изготовления блюда | datetime | да | Прил. 4 граф 1 |
| 2 | Время снятия бракеража | time | да | Прил. 4 граф 2 |
| 3 | Наименование блюда | text (из меню) | да | Прил. 4 граф 3 |
| 4 | Результат органолептической оценки (отлично/хорошо/удовл./неудовл.) | select | да | Прил. 4 граф 4 |
| 5 | Разрешение к реализации (РАЗРЕШЕНО / ЗАПРЕЩЕНО) | select | да | Прил. 4 граф 5 |
| 6 | Подписи членов бракеражной комиссии | signatures (multi) | да | Прил. 4 граф 6 |
| 7 | Результаты взвешивания порционных блюд, г | number | да для порционных | Прил. 4 граф 7 |
| 8 | Примечание | text | условно (если оценка ниже отлично) | Прил. 4 граф 8 |

**Критерии оценки** (граф 4): внешний вид, консистенция, цвет, запах, вкус.

## Ритм

- **Frequency:** event-driven (перед каждой раздачей блюда)
- **Per row:** ОДНО блюдо = ОДНА строка. Иногда 5-15 блюд за смену.
- **Кто инициирует:** повар / шеф-повар после готовки → бракеражная комиссия

## Роли

- **Filler:** повар / шеф-повар (заполняет графы 1-4, 7)
- **Verifier (комиссия 1-3 чел.):** утверждают графу 5 «РАЗРЕШЕНО / ЗАПРЕЩЕНО»,
  проставляют подписи (граф 6)

## Pipeline (TF task wizard)

1. **Шаг 1** «Что готовим?» — поле «Наименование блюда» из меню (autocomplete)
2. **Шаг 2** «Технологическая обработка завершена» — datetime + temperature (≥70°C)
3. **Шаг 3** «Бракераж органолептический»:
   - вид (select) · запах (select) · вкус (select) · консистенция (select)
4. **Шаг 4** «Решение комиссии» — РАЗРЕШЕНО / ЗАПРЕЩЕНО + причина (если 2-я)
5. **Шаг 5** (для порционных) «Контрольное взвешивание» — number

photoMode: required для шага 3 (фото готового блюда + порции для evidence).

## Compliance rule

Не daily-rule — event-driven. «Заполнено сегодня» = есть >0 записей
с date=today (хотя бы одно блюдо забраковано).

## Edge cases

- **«ЗАПРЕЩЕНО»:** обязательный комментарий + auto-create CAPA-ticket
  «брак готовой продукции — устранение причин».
- **Порционное vs весовое блюдо:** граф 7 (взвешивание) только для
  порционных. Маркер `isPortionable` в config.

## TasksFlow flow

- **Type:** event-driven (rolling). Кнопка «+ блюдо» → сразу новая задача.
- **rowKey:** `dish-event::{timestamp}`
- **Verifier:** обязательно (бракеражная комиссия).

## Срок хранения

12 мес. (внутренний регламент соц.учр.).
