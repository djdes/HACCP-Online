# Journal `incoming_control` — Журнал входного контроля сырья

**Tier:** C (ХАССП-рекомендуемый, обязателен для крупных производств)
**СанПиН:** п. 3.2 СанПиН 2.3/2.4.3590-20 (приёмка только сопроводительных документов)

## Назначение

Контроль качества поступающего сырья: сверка накладной, органолептика,
сертификаты безопасности, температура доставки. Защита от brak'а на этапе
поставки.

## Колонки

| # | Колонка | Тип | Обяз. |
|---|---------|-----|-------|
| 1 | Дата приёмки | date | да |
| 2 | Поставщик | text | да |
| 3 | Наименование сырья | text | да |
| 4 | № партии | text | да |
| 5 | Количество (кг/л/шт) | number | да |
| 6 | № документа о безопасности | text | да |
| 7 | Срок годности | date | да |
| 8 | Температура доставки, °C | number | для скоропорт. |
| 9 | Органолептическая оценка (ОК / отклонение) | select | да |
| 10 | Принято / Отклонено | select | да |
| 11 | Причина отклонения | text | если отклонено |
| 12 | Подпись принимающего | signature | да |

## Ритм

Event-driven (при каждой поставке). Кладовщик создаёт запись в TF.

## Pipeline (TF task)

1. Шаг 1 — Сканировать ТТН (photo)
2. Шаг 2 — Заполнить поля партии
3. Шаг 3 — Органолептика
4. Шаг 4 — Решение (принято/отклонено)

photoMode: required на шаге 1.

## Связи

- Сгенерированный `batchKey` идёт в **traceability_test** (прослеживаемость)
- При **«Отклонено»** → CAPA-ticket «возврат поставщику»

## TasksFlow flow

- **Type:** event-driven, rolling.
- **rowKey:** `delivery::{timestamp}::{batchKey}`
