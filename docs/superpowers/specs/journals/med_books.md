# Journal `med_books` — Электронные медицинские книжки

**Tier:** C (ХАССП-рекомендуемый, обязателен по СанПиН для пищевиков)
**СанПиН:** п. 2.21 СанПиН 2.3/2.4.3590-20 + Приказ № 84

## Назначение

Хранилище записей о медосмотрах per-сотрудник. Без действующей мед.книжки
сотрудник не может работать в общепите.

## Колонки (per-сотрудник)

| # | Колонка | Тип |
|---|---------|-----|
| 1 | Сотрудник | text (auto, primary key) |
| 2 | № медицинской книжки | text |
| 3 | Дата выдачи | date |
| 4 | Дата окончания (annual) | date |
| 5 | Скан мед.книжки (страницы 1, 2, последний осмотр) | photo (multiple) |
| 6 | Тип последнего осмотра | text |
| 7 | Результат | select (Допущен / Не допущен) |
| 8 | Дата следующего планового осмотра | date |

## Ритм

Per-сотрудник: ежегодное обновление (мед.осмотр раз в год) + санитарный
минимум раз в 2 года.

## TasksFlow flow

- **Type:** event-driven (reminder за 60/30/7 дней до окончания);
  + в day одно sotrudник создаётся reminder
- **rowKey:** `medbook::{userId}::{periodEnd}`

## Compliance rule

Сотрудник без действующей мед.книжки → red flag (нельзя работать).
N сотрудников с просрочкой → красный bar на дашборде.

## Связи

- При просрочке → сотрудник auto-blocked для назначения task'ов через
  bulk-assign-today (отфильтровывается из linkedUserIds).
- Связь с `User.medBookExpiresAt` (если поле есть в schema; иначе хранится
  в JournalDocumentEntry).
