# Journal `climate_control` — Журнал учета температуры и влажности в складских помещениях

**Tier:** A (СанПиН-обязательный для всех общепит со складом)
**СанПиН:** Прил. № 3 к СанПиН 2.3/2.4.3590-20
**Status:** draft

## Назначение

Контроль микроклимата сухих складов и кладовых. Гарантирует что условия
хранения сырья соответствуют ТУ продуктов (не выше +18°C, влажность 50-70%
для большинства категорий).

## Ритм

- **Frequency:** daily (1×/день для большинства; при критичном товарообороте —
  2×/день в фиксированные слоты, например 09:00 и 17:00)
- **Per row:** ОДНО помещение × ОДИН слот замера = ОДНА строка
- **Кто инициирует:** TF auto-fan-out утром (опц. ещё в обед)

## Роли

Filler — кладовщик / повар / любой сотрудник.
Verifier — заведующая (опционально).

## Pipeline (TF task)

1. **Шаг 1** «Сними показания термогигрометра {помещение}»:
   - field: temperature (number, range -10..+30)
   - field: humidity (number, range 20..95)
2. **Шаг 2** (условный) «Параметры вне нормы — что сделал» — required text + photo

## Compliance rule

`DEEP_INSPECT_CODES` includes `climate_control` — структура `entry.data`:
```
{ measurements: { roomId: { time: { temperature, humidity } } } }
```
Filled = для каждого `(room, controlTime)` слота есть значение.

## Edge cases

- **Жара летом:** температура склада может превысить норму на пиках.
  Ожидаемое отклонение → причина + меры (включить кондиционер, перенести
  в холодильник).
- **Один гигрометр на несколько помещений:** настраивается per-room,
  но менеджер может пометить как группу в config.

## TasksFlow flow

- **Type:** N задач (1 на helper-помещение × кол-во controlTimes/день)
- **rowKey:** `room::{roomId}::time::{HH:MM}`

## Срок хранения

3 мес. (как и cold_equipment).
