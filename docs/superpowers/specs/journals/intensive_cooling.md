# Journal `intensive_cooling` — Журнал контроля интенсивного охлаждения горячих блюд

**Tier:** C (ХАССП-рекомендуемый, критично для ХАССП)
**СанПиН:** п. 5.4 СанПиН 2.3/2.4.3590-20 (правило «65 → 5°C за ≤6 ч»)

## Назначение

Контроль скорости охлаждения готовых горячих блюд для последующего
хранения. По СанПиН: с 65°C до 5°C должно остыть **за ≤6 часов**.
Иначе — зона 60-5°C критична для размножения патогенов.

## Колонки

| # | Колонка | Тип |
|---|---------|-----|
| 1 | Дата | date |
| 2 | Наименование блюда | text |
| 3 | Время начала охлаждения (t° ≥ 65°C) | datetime |
| 4 | Температура в начале, °C | number |
| 5 | Время достижения 5°C | datetime |
| 6 | Длительность охлаждения, мин | number (auto) |
| 7 | Куда перемещено (камера) | text (auto из equipment) |
| 8 | Подпись повара | signature |
| 9 | В пределах нормы? | boolean (auto: длительность ≤ 360 мин) |

## Ритм

Event-driven (rolling) — каждое блюдо после готовки.

## Pipeline (TF task)

1. Шаг 1 — Зафиксируй блюдо вышло из плиты (t° + datetime, photoMode: required для термометра)
2. Шаг 2 — Перемести в холодильник интенсивного охлаждения
3. Шаг 3 — Через 6 часов проверь t° ≤ 5°C (datetime + temperature reading)

## Compliance rule

Длительность > 6 ч → red flag, auto-CAPA «нарушение цепи холода».
Compliance не падает если за день нет горячих блюд.

## TasksFlow flow

- **Type:** event-driven, rolling
- **rowKey:** `cooling::{dishName}::{startTimestamp}`
