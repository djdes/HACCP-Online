# Journal `perishable_rejection` — Журнал бракеража скоропортящейся пищевой продукции

**Tier:** B (обязательный для соц.учр., школ, садов, больниц с большими объёмами молочной продукции)
**СанПиН:** Прил. № 5 к СанПиН 2.3/2.4.3590-20
**Status:** draft

## Назначение

Контроль приёмки + реализации скоропортящихся продуктов (молочка,
мясо/рыба, готовая еда от внешних поставщиков). Прослеживаемость
партии от поставки до подачи.

## Ритм

- **Frequency:** event-driven (при приёмке каждой партии + при списании/реализации)
- **Per row:** ОДНА партия = ОДНА строка
- **Кто инициирует:** Кладовщик при получении товарной накладной

## Роли

- **Filler (при приёмке):** кладовщик / товаровед
- **Filler (при реализации):** повар / комиссия
- **Verifier:** заведующая (одобряет приёмку, утверждает списание)

## Pipeline (TF task)

При приёмке:
1. Шаг 1 — Сканировать накладную (photo) или ввести данные вручную
2. Шаг 2 — Органолептика (select)
3. Шаг 3 — Зафиксировать партию (auto generate batchKey для traceability)

При реализации:
1. Шаг 1 — Выбрать партию из списка активных
2. Шаг 2 — Указать дату/час реализации + количество

## Compliance rule

Event-driven. Compliance не падает если за день нет приёмок (нормально).
Сигнал тревоги — если **есть приёмка** но **нет органолептики** или
просрочена.

## Edge cases

- **Просроченная партия:** auto-redflag + блокировка для использования.
- **«Неудовлетворительно» при приёмке:** возврат поставщику, протокол
  забраковки, CAPA-ticket.
- **Связь с traceability:** каждая запись генерирует/использует `batchKey`
  для журнала прослеживаемости.

## TasksFlow flow

- **Type:** event-driven (rolling).
- **rowKey:** `delivery::{timestamp}::{batchKey}` (приёмка) или `usage::{batchKey}::{timestamp}` (списание)
